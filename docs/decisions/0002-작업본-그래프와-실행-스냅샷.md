# ADR 0002. 앱 작업본 그래프(draft_graph)와 실행 그래프 스냅샷

- 상태: 채택
- 날짜: 2026-11-03

## 배경
설계서 §6은 빌더 에이전트가 서버에서 툴(`add_node` 등)로 그래프를 고치게 한다. §9는 "미저장 변경은 로컬에 유지"라고 적었다.
빌더가 서버에서 그래프를 고치려면 서버가 "지금 편집 중인 그래프"를 알아야 한다. 버전(`workflow_versions`)은 검증을 통과한 저장본이라 편집 중 상태를 담을 수 없다.
또 `run_test`와 캔버스의 "테스트 실행"은 아직 버전으로 저장하지 않은 그래프를 실행해야 한다.

## 결정
1. `apps.draft_graph jsonb` 컬럼을 추가한다. 빌더 툴과 캔버스 편집은 이 작업본을 고친다. 캔버스는 편집 후 잠시 뒤 `PUT /apps/{id}/draft`로 서버에 반영한다.
2. "버전 저장"은 작업본을 검증하고 통과하면 새 `workflow_versions` 행으로 고정한다. 검증 실패면 저장하지 않고 노드별 오류를 돌려준다.
3. `runs.graph_snapshot jsonb` 컬럼을 추가하고 `runs.version_id`는 비워 둘 수 있게 한다. 테스트 실행은 실행 시점의 작업본을 스냅샷으로 남긴다. 배포 실행은 버전을 가리킨다.
4. `runs.approval jsonb`(승인 요청 노드 id, 승인자, 결과)와 `runs.context jsonb`(재개용 노드 출력)을 추가한다. 승인 대기 후 재개에 필요하다.
5. `documents.error text`, `documents.content bytea`, `market_items.bundle_path text`를 추가한다. 실패 사유 표시, 워커가 처리할 원본 파일, 기본 제공 번들 위치 기록용이다.
6. `runs.created_at`, `runs.created_by`를 추가한다. 실행 이력 정렬·필터와 승인자 확인용이다.
7. (마이그레이션 0002) 외래 키 삭제 규칙: `deployments.version_id` CASCADE, `runs.version_id`·`messages.run_id` SET NULL. 앱을 지울 때 막히지 않게 한다.
8. (마이그레이션 0003) `run_steps.seq`를 추가한다. Windows 시계 해상도(약 15ms) 때문에 시작 시각이 같은 단계가 생겨 순서가 섞이는 문제를 막는다.

## 대안
- 프런트 로컬에만 작업본을 두고 빌더 요청마다 그래프 전체를 보낸다: 여러 탭과 빌더가 동시에 고칠 때 덮어쓰기가 생기고, 빌더 세션을 다시 열 때 상태를 잃는다.
- 매 툴 호출마다 버전을 만든다: 버전 목록이 쓰레기로 가득 차고, 검증 실패 상태를 저장할 수 없다.

## 영향
- 설계서 §3-2에 컬럼 설명을 추가했다. 기존 컬럼은 바꾸지 않았다.
- 빌더와 캔버스가 같은 작업본을 고치므로, 빌더 응답의 `graph_patch`에는 변경 연산과 함께 최신 그래프 전체를 담아 프런트가 어긋나지 않게 한다.
