# ADR 0006. 개인 설정과 프로젝트

- 상태: 채택
- 날짜: 2026-11-03

## 배경
사용자 요청: "개인 설정 화면(테마 등)", "개인별로 사용할 때 프로젝트별로 관리가 되어야 한다".
설계서 §3은 조직 → 워크스페이스 → 앱 구조만 있어, 한 워크스페이스 안에서 여러 사람이 각자 일을 나눠 관리할 단위가 없었다.

## 결정
### 개인 설정
- `users.preferences jsonb`(마이그레이션 0005): 테마(light·dark·system), 글자 크기(normal·large), 기본 워크스페이스, Enter로 보내기.
- 계정에 저장해 다른 기기에서도 따라온다. 화면은 깜빡임을 막으려고 브라우저 저장소 값을 먼저 쓰고 서버 값으로 맞춘다.
- 비밀번호 바꾸기는 지금 비밀번호를 확인한 뒤에만 한다(활동 기록에 남김).
- 다크 모드는 Tailwind 색(slate·white·옅은 강조색)을 CSS 변수로 바꿔, 컴포넌트를 하나하나 고치지 않고 모든 화면에 적용한다.

### 프로젝트
- `projects`, `project_members` 테이블, `apps.project_id`·`knowledge_bases.project_id`(마이그레이션 0006, 모두 추가).
- 공개 범위 2가지: `workspace`(워크스페이스 멤버 모두) / `private`(만든 사람·초대한 멤버·소유자·관리자).
- 접근 제어는 `require_role` 한 곳에서 한다. 경로 대상(앱·실행·대화·주석·API 키·배포·지식베이스·문서·조각)이 비공개 프로젝트에 속하면 볼 수 없는 사람에게 404로 숨긴다. 목록(앱·지식베이스·실행 기록)도 같은 규칙으로 거른다. 빌더 에이전트의 지식베이스 목록도 거른다.
- 역할 권한(§3-1)은 그대로다. 프로젝트는 "볼 수 있는 범위"만 좁힌다.
- 소유자·관리자는 관리 목적으로 모든 프로젝트를 본다.
- 프로젝트를 지워도 앱·지식베이스는 지우지 않고 '프로젝트 없음(공용)'으로 옮긴다.
- 공개 챗·위젯·서비스 API는 배포·API 키 기준이라 프로젝트와 무관하게 동작한다.

## 대안
- 사람마다 워크스페이스를 따로 두기: 이미 가입 시 개인 워크스페이스가 생기지만, 팀 워크스페이스 안에서 개인 작업을 나누려면 워크스페이스를 오가야 하고 연결 정보·지식베이스를 공유할 수 없다.
- 필드 단위 ACL: CLAUDE.md 범위 밖.

## 영향
- 기존 앱·지식베이스는 project_id가 비어 있어 지금처럼 모두에게 보인다.
- 관리 콘솔의 개요·사용량은 워크스페이스 전체 기준(관리자 전용)이라 그대로다.
