# ADR 0007. 로그인 화면 정리와 관리자 계정 관리

- 상태: 채택
- 날짜: 2026-11-03

## 배경
사용자 요청: "로그인 화면에 사용자 권한별 나와 있는 것 빼고, 관리자 기능에서 관리하게 해 달라", "로그인 화면에 그럴싸한 인터랙션".
로그인 화면이 역할별 데모 계정과 공용 비밀번호를 누구에게나 보여 주고 있었다. 주소가 인터넷(Funnel)에 열려 있어 누구나 소유자로 들어올 수 있는 상태였다.
관리자가 계정을 내줄 방법은 초대 링크뿐이라, 링크를 받은 사람이 직접 가입해야 했다.

## 결정
- `GET /auth/demo-accounts`와 시스템 설정 `show_demo_accounts`를 없앤다. 데모 계정 자체(시드)는 그대로 둔다.
- 관리 콘솔 > 멤버에 **계정 만들기**(`POST /workspaces/{ws}/admin/accounts`)와 **비밀번호 재설정**(`POST /workspaces/{ws}/members/{id}/reset-password`)을 더한다.
  - 임시 비밀번호는 서버가 12자(헷갈리는 글자 제외)로 만들고 응답에서 한 번만 돌려준다. 해시만 저장하고 활동 기록에는 남기지 않는다.
  - 소유자·관리자 계정은 소유자만 만들거나 재설정한다(역할 바꾸기·내보내기 규칙과 같다). 내 비밀번호는 내 설정에서만 바꾼다.
  - 다른 워크스페이스에도 속한 계정은 재설정할 수 없다. 한 워크스페이스 관리자가 남의 계정 전체를 가져가는 것을 막는다.
  - 이미 가입된 이메일로는 만들지 않고 초대하기를 안내한다(본인 동의 없이 워크스페이스에 넣지 않는다).
- 로그인 화면은 넓은 화면에서 "요청 → 흐름" 시연을, 입력 카드에는 비밀번호 보기, Caps Lock·한글 경고, 이메일 기억, 실패 흔들림, 성공 표시를 넣는다. 외부 라이브러리 없이 CSS·SVG로 만들고, 움직임 줄이기 설정을 따른다.

## 대안
- 데모 계정 표시를 기본값만 끄기: 공개 API가 남아 다시 켜질 수 있고, 관리자가 계정을 내주는 문제는 그대로다.
- 첫 로그인 때 비밀번호 바꾸기 강제: users 열 추가가 필요하다. 이번에는 안내 문구로 대신하고 후보로 남긴다.

## 영향
- 기존 데모 계정의 공용 비밀번호는 여전히 유효하다. 공개 상태라면 운영자가 바꿔야 한다(runbook).
