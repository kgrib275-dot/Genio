# ADR 0008. v0.4 자동 실행·데이터 표·캔버스·챗 경험

- 상태: 채택
- 날짜: 2026-11-03

## 배경
사용자 요청: "Dify, n8n 등 비슷한 서비스의 좋은 기능을 찾아 다 붙이고, 챗봇과 엮은 부분 UI/UX도 고려해 달라".
Dify 기능은 v0.2(ADR 0005, docs/dify-gap.md)에서 대부분 들어왔다. 남은 빈칸은 자동화 도구(n8n·Zapier·Make)의 실행 방식·블록·캔버스 편의와, 챗봇 도구(Flowise·Dify 웹앱·ChatGPT류)의 대화 경험이다. 조사 결과는 docs/dify-gap.md §6~8.

## 결정
### 1. 자동 실행(트리거) — n8n Webhook/Schedule, Zapier·Make 예약
- `app_triggers` 테이블(마이그레이션 0007). kind = `webhook` | `schedule`.
- 웹훅: 앱마다 비밀 주소 `POST|GET /api/v1/hooks/{token}`. 본문(JSON)·쿼리가 입력이 된다. `mode=async`면 바로 run_id를, `sync`면 최대 30초 기다려 결과를 돌려준다(n8n "Respond to Webhook"). 토큰 다시 만들기·끄기 가능. 저장한 버전으로만 실행한다(작업본은 테스트 실행 전용).
- 예약: cron 식(+ 쉬운 선택: 매시간·매일·평일·매주) + 시간대(기본 Asia/Seoul) + 고정 입력. Celery beat(워커 `-B`)가 1분마다 `next_run_at`이 지난 예약을 실행한다. 최소 간격 1분. cron 해석은 `croniter`.
- 실패하면 다른 앱 실행(n8n Error Workflow): 앱 기능 설정 `on_failure.app_id`. 실패 정보(앱 이름·run_id·오류·입력)를 입력으로 넘긴다. 실패 처리 앱이 다시 실패해도 또 부르지 않는다(무한 반복 방지).
- 실행 다시 하기: 지난 실행의 입력(고쳐서도 가능)과 같은 버전으로 새 실행.

### 2. 새 블록 — n8n Wait·Edit Fields·Date & Time·Execute Workflow·Data Table
- `wait` 기다리기(1~300초), `set_fields` 값 정리, `date_time` 날짜·시간(지금·형식 바꾸기·더하기·차이), `run_app` 다른 앱 실행(하위 흐름, 깊이 제한 공유), `data_table` 데이터 표(추가·덮어쓰기·찾기·가져오기·목록·지우기·개수).
- 데이터 표: `data_tables`, `data_rows`(JSON 값, 선택적 고유 키). 워크스페이스 단위, 프로젝트 공개 범위를 따른다. 화면에서 행 보기·고치기·CSV 가져오기/내보내기.
- 병렬 분기(Merge 대기)는 CLAUDE.md 범위 밖이라 넣지 않는다(합치기는 기존 variable_aggregator).

### 3. 캔버스 — n8n 편의
- 그래프에 `notes`(메모), 노드에 `disabled`(끄기)를 더한다(schemas/graph.py 한 곳, 프런트 타입은 생성). 둘 다 비어 있으면 저장 형식이 그대로라 기존 그래프·스냅샷이 바뀌지 않는다.
- 끈 블록은 실행하지 않고 "건너뜀"으로 기록하며 입력을 그대로 다음으로 넘긴다. 분기 블록을 끄면 첫 번째 출구로 간다.
- 복사·붙여넣기·복제, 되돌리기·다시 하기, 미니맵, 자동 정렬, cURL 붙여넣기로 HTTP 블록 채우기.

### 4. 챗 경험 — Flowise·Dify 웹앱
- 답변 실시간 표시: LLM 어댑터 `complete(on_delta=)`가 글 조각을 넘기고, 실행 이벤트 채널(Redis)에 `delta`로 흘린다. 공유 챗 SSE는 이를 `delta` 이벤트로 전달하고 마지막 `answer`가 최종 글로 바꾼다. 출력 검열을 켠 앱은 조각을 보내지 않는다(검열 전 글 노출 방지).
- 답변 마크다운(표·코드·목록), 복사·다시 답하기·멈추기, 이전 대화 목록과 새 대화, 대화 내보내기, 아래로 가기, 입력칸 자동 늘리기.
- 위젯 모양(Flowise theme): `deployments.appearance` — 색, 위치, 버튼 글, 인사 말풍선, 창 크기, 처음부터 열기.
- 빌더 안 "대화로 시험하기"(Dify Debug & Preview): 작업본으로 대화해 보고, 로그에는 섞지 않는다.

## 대안
- 예약을 OS cron으로: 컨테이너 밖 설정이 생겨 docker-compose 한 번으로 뜨는 원칙에 맞지 않는다.
- 데이터 표를 외부 DB 연결로만: 비개발자가 10분 안에 쓰기 어렵다.
- 진짜 토큰 스트리밍 대신 화면에서 한 글자씩 보여 주기: 첫 글자가 늦게 나오는 문제는 그대로라 채택하지 않았다.

## 영향
- 워커가 beat를 함께 돌린다(컨테이너 1개 유지). 워커가 둘 이상이면 beat는 하나만 켜야 한다(runbook).
- 웹훅 주소는 비밀값처럼 다룬다. 로그·오류에 토큰을 남기지 않는다.
- Google 연결은 조각 스트리밍 없이 다 만든 답을 한 번에 보낸다.
