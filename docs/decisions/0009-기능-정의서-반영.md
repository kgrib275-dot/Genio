# ADR 0009. 기능 정의서(docs/feature-spec.md) 반영 — v0.5

- 상태: 채택
- 날짜: 2026-11-03

## 배경
사용자가 "작업 필수 내용"으로 기능 정의서를 주었다. 정의서는 기능 범위의 기준이고(design.md는 구현 방식의 기준), P0 = 프로토타입 필수, P1 = 정식 출시 필수, P2 = 이후다.
v0.4까지 대부분이 들어왔지만 대조해 보니 P0 빈칸이 남아 있었다(값 끌어오기, 실행 결과 문장 설명, 승인 링크·반려 분기, DB 커넥터, 연결 테스트, 웹훅 서명, DOCX, 문서 켜기·끄기, Azure, 모델 목록, 사용자별 비용, 배포 대상 사용자, API 키 권한 범위, JS 코드, 특정 단계부터 다시 실행, 샘플 입력, 워크플로우 앱 공유 폼, 업무 용어 등).

## 결정
- 정의서를 `docs/feature-spec.md`로 두고, 항목별 반영 현황을 `docs/feature-coverage.md`에서 관리한다. CLAUDE.md에서 기준 문서로 가리킨다.
- 이번(v0.5)에는 **P0 전부**와, 구현 범위가 작고 정의서의 강점(S7·S8·S9·S10)과 이어지는 **P1 일부**를 넣는다: 질문·배정 단계와 작업함, 상담원 전환, 실패·비용 알림, 월 한도, 로그 보존 기간, PPTX·XLSX·HTML, 한국 커넥터 3개(잔디·네이버웍스·카카오 알림톡), 업무 단위 템플릿.
- 다음으로 미루는 P1/P2: OAuth2, SSO(CLAUDE.md 범위 밖), 카카오톡·슬랙·팀즈 채널 배포, 비전 모델, 버전 diff, 병합(병렬 분기는 CLAUDE.md 범위 밖), 사내 마켓, 외부 판매, 노션 등 동기화, 온프레미스. feature-coverage.md에 남긴다.
- DB 변경은 마이그레이션 0008(추가만): deployments.allowed_users, app_api_keys.scopes, app_triggers.secret_encrypted·last_payloads, documents.enabled, builder_sessions.metrics, apps.test_inputs, conversations.status·assigned_to, human_tasks 테이블.
- 빌더 툴에 `get_run`(실행 결과 읽기)을 더한다. CLAUDE.md의 툴 목록을 함께 고친다. "설명 모드·자동 시험·오류 해결"(S1)에 필요하다.
- 업무 용어(S2): 노드 → 단계, 웹훅 → 외부에서 받기, 변수 → 값. 표현식 `{{ }}`는 "값 끌어오기" 버튼 뒤로 숨기고 고급 모드에서만 직접 쓴다. 개발자 용어는 설정 화면에만 남긴다(CLAUDE.md 문구 규칙).
- 실행 결과(S3): `engine/describe.py`가 단계마다 한 문장(`summary`)과 실행 전체 이야기(`story`)를 만든다. JSON은 펼쳐 보기.
- 공개 챗 속도 제한 키를 앱별로 나눈다(`chat:{app_id}:{ip}`). 신뢰하는 프록시가 붙인 IP만 쓰고, 로그인 시도 제한·비밀번호 규칙·보안 헤더를 더한다(부하 시험 보고서의 보안 과제).

## 대안
- P1까지 한 번에 모두: OAuth2·채널 배포·SSO는 외부 앱 등록·심사가 필요해 이 PC에서 끝까지 확인할 수 없다.
- 용어를 그대로 두기: 정의서가 P0로 요구한다.

## 영향
- 화면 문구가 바뀌어 사용설명서·도움말도 함께 고친다.
- 사람 개입(승인·질문·배정)은 링크로도 처리할 수 있어, 로그인하지 않은 사람에게도 이메일·슬랙으로 요청을 보낼 수 있다(링크 토큰은 비밀값처럼 다룸).
