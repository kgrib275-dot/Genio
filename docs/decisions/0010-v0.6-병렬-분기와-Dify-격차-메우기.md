# ADR 0010. 병렬 분기와 Dify 격차 메우기 — v0.6

- 상태: 채택
- 날짜: 2026-11-04

## 배경
사용자가 Dify와 비교해 남은 격차를 모두 넣어 달라고 요청했다(2026-11-04). 지금 단계는 "아이데이션" 성격의 프로토타입이라, 기능을 넓게 넣어 본 뒤 어떤 기능을 살릴지 고르기로 했다.
- 병렬 분기: 여러 사용자와 많은 동시 접속(1,000명 기준) 조건에서 검증한다. CLAUDE.md는 이 기능을 '범위 밖'으로 두고 있었다.
- 기타 격차: 모델 공급자 수, 마켓 크기, 비전 모델, 대화 기억 요약, 버전 비교, MCP 서버 게시, 외부 추적(Langfuse·LangSmith), 지식베이스 Q&A 쪼개기와 문서 처리 파이프라인.

## 결정
1. **병렬 분기를 범위 안으로 옮긴다.** CLAUDE.md의 '하지 않는 것'에서 뺀다.
   - 한 출구에서 여러 선이 나가면 그 갈래들을 동시에 실행한다.
     - 실행당 동시 실행 수는 `GENIO_RUN_PARALLELISM`(기본 4, 최대 16)이다.
     - 동시에 도는 갈래는 갈래마다 DB 연결을 따로 쓴다.
     - 혼자 도는 단계는 지금처럼 메인 연결로 실행한다. 그래서 기존 흐름은 동작이 바뀌지 않는다.
   - 들어오는 선이 여러 개인 단계는 모든 선이 정해질 때까지 기다린다(n8n Merge의 "모두 기다림").
     - 고르지 않은 분기나 실패하지 않은 단계의 '실패 길'은 '안 간 길'로 표시한다. 그 아래도 차례로 '안 감'이 된다(dead path elimination).
     - 그래서 조건 분기를 한 단계로 다시 모으는 기존 흐름도 그대로 동작한다.
   - 사람을 기다리는 단계(승인·질문·배정)는 한 번에 하나만 연다.
     - 나머지 갈래는 끝까지 실행한 뒤 실행을 멈춘다.
     - 할 일(HumanTask)은 실제로 멈출 때 만든다. 다른 갈래가 도는 동안 결정이 들어오는 경쟁을 막기 위해서다.
     - 상태(끝난 단계, 정해진 선, 준비된 단계)는 `run.context.sched`에 저장해 이어서 실행한다.
     - 작업함 결정은 지금 기다리는 단계의 일일 때만 실행을 깨운다.
   - 한 갈래가 '멈춤'으로 실패하면 새 단계는 띄우지 않는다. 이미 도는 갈래가 끝나면 실행을 실패로 끝낸다.
   - '이 단계부터 다시'는 그 단계 아래쪽만 다시 실행하고, 나머지 단계의 결과는 지난 실행 것을 쓴다(실행 순서와 무관).
   - 빌더 툴 `add_node`·`connect`에 `parallel`(기존 선을 두고 갈래를 하나 더) 옵션을 더한다. 시스템 프롬프트에 사용 기준을 적는다.
   - 캔버스에는 "동시 N갈래"와 "갈래 N개 모음" 표시를 붙인다.
2. MCP 서버 게시와 외부 추적 연동도 범위 안으로 옮긴다. 둘 다 연결 정보·키로 보호하고, 비밀값은 마스킹한다.
3. 나머지 격차는 기능 정의서 P1 항목으로 넣고, 반영 현황을 `feature-coverage.md`에 적는다.
   - 대상: 비전, 요약 기억, 버전 비교, 공급자 확대, 마켓 확대, 지식베이스 Q&A·파이프라인.
4. 온프레미스 LLM은 계속 범위 밖이다. 다만 'OpenAI 호환' 연결로 사내 서버 주소를 넣는 것은 이미 된다.

## 대안
- 갈래마다 Celery 작업을 따로 띄우기: 실행 상태를 여러 작업이 나눠 써야 해서 잠금과 경쟁 조건이 늘어난다. 한 실행 안의 스레드 풀이 단순하다.
- 합치는 단계가 "먼저 온 갈래"로 바로 실행되게 하기: 값이 빠진 채 실행되므로 하지 않는다. 대신 n8n의 '모두 기다림'만 둔다.

## 영향
- `engine/executor.py`의 실행 루프가 '준비된 단계 묶음' 방식으로 바뀐다.
  - 승인 대기 중이던 예전 실행은 기다리던 단계 아래만 이어서 실행한다(호환 처리).
- 검증기는 "한 단계에서 여러 곳으로 갈 수 없어요" 오류를 더 내지 않는다.
- 한 실행이 DB 연결을 최대 `GENIO_RUN_PARALLELISM`개 더 쓸 수 있다.
  - 워커 동시성 × 병렬 수가 DB 연결 한도(200) 안에 들어오게 운영 설정을 둔다(runbook).
