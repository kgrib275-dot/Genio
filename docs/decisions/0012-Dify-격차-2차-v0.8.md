# ADR 0012. Dify 격차 2차 메우기 — v0.8

- 상태: 채택
- 날짜: 2026-11-05

## 배경
dify.ai/ko와 공식 문서(docs.dify.ai)를 다시 읽고 Genio와 비교했다(2026-11-05). 지난 비교(ADR 0010) 이후 Dify에 생긴 기능과, 영업에서 부족한 부분을 목록으로 만들었고, 사용자가 우선순위 1~6번을 순서대로 진행하라고 했다.

## 결정 (순서대로)
1. **일괄 실행 + 단계 하나만 실행 + 값 확인창**
   - 흐름 앱에서 CSV·XLSX로 여러 건을 한 번에 처리하고 결과를 표로 내려받는다.
   - 캔버스에서 선택한 단계 하나만 샘플 값으로 시험한다. 실행 결과의 값은 검색·복사할 수 있는 창으로 본다.
2. **MCP 클라이언트 + 연동 늘리기**
   - 외부 MCP 서버를 연결 정보로 등록하고, 단계와 에이전트에서 그 서버의 도구를 쓴다.
   - OpenAPI 명세를 가져와 도구를 자동으로 만든다.
   - 커넥터를 10개 이상 더 넣는다.
3. **지식 데이터 소스**
   - Notion 동기화, 웹사이트 여러 쪽 가져오기, 공개 Google 문서 가져오기, 외부 지식베이스 API 연결, 검색 튜닝(대표 질문 세트)을 넣는다.
4. **운영 안전**
   - 올린 파일을 S3 호환 저장소나 디스크에 둘 수 있게 한다(기본은 지금처럼 DB).
   - 코드 실행을 별도 격리 서비스(샌드박스)로 옮긴다.
   - Sentry는 선택 기능으로 둔다.
5. **편의·배포**
   - Ctrl+K 전체 검색창과 단축키 목록, 스니펫(단계 묶음 재사용), 웹앱 로고, IP 접근 제한, 공개 API 문서와 명령줄 도구를 넣는다.
6. **Dify 앱 가져오기**
   - Dify DSL(YAML)을 제니오 흐름으로 바꿔 새 앱으로 만들고, 바뀌지 않은 부분은 변환 보고서로 알려 준다.

## 이번에 하지 않는 것 (범위 밖 유지)
SSO(SAML·OIDC)·SCIM, 결제·요금제·크레딧, 다중 워크스페이스 관리, 고객 키 관리(BYOK), 쿠버네티스·Terraform 배포, 사용자 정의 역할. CLAUDE.md의 '하지 않는 것' 또는 외부 계약이 필요한 항목이라, 판매형으로 바꿀 때 따로 결정한다.

## 대안
- 플러그인 제3자 등록(외부 개발자가 만들어 설치): 외부 판매자 등록이 범위 밖이라 하지 않고, 커넥터를 직접 늘리고 OpenAPI 가져오기·MCP 클라이언트로 대신한다.
- Google 드라이브 비공개 파일: OAuth 앱 등록·심사가 필요해 이번에는 '링크가 있는 공개 문서'만 지원한다.

## 영향
- DB 변경은 마이그레이션 0013(파일 저장 위치)과 0014(스니펫, 접근 허용 IP) 두 개이고 모두 추가만 한다.
- 새 외부 의존: `boto3`(S3, 선택), `PyYAML`(Dify 가져오기), `sentry-sdk`(선택).
- 코드 실행 샌드박스는 별도 컨테이너로 늘어난다. 설정하지 않으면 지금처럼 서버 안에서 실행한다.
- 실제 Notion·S3·MCP 서버·Dify 앱 내보내기 파일로는 확인하지 못하는 부분이 있다. 가짜 서버와 직접 쓴 시험 자료로만 확인한다.
