# ADR 0015. 경쟁 서비스 조사 반영 1차

- 상태: 채택
- 날짜: 2026-11-18

## 배경
n8n·Dify·Zapier·Make 등 17개 서비스의 2025~2026년 기능을 조사해(`docs/competitor-review-2026-11-18.html`) Genio에 없거나 일부만 있는 것 53개를 골랐다. 그중 "먼저 하면 좋은 10가지"를 순서대로 진행했다.

## 결정
1. **X1 빌더 되돌리기**: 빌더가 한 차례에 흐름을 바꾸면 바꾸기 전 모습과 바꾼 뒤 모습의 지문을 그 차례 기록(`builder_messages.graph_patch.checkpoint`)에 남긴다. 되돌린 뒤 흐름이 더 바뀌었으면 확인을 한 번 더 받는다. 화면에는 흐름 전체를 보내지 않는다. 마이그레이션 없음.
2. **X2 먼저 계획 보기**: 메시지에 `plan_only`를 켜면 서버가 흐름을 바꾸거나 실행하는 툴(add·update·remove·connect·run_test)을 막는다(프롬프트 부탁이 아니라 코드로). 시스템 프롬프트 본문(`system.md`)은 건드리지 않고 차례마다 덧붙인다.
3. **X6 실패 자동 진단**: 실행 상세에 `diagnosis`(규칙 기반 제안)를 넣는다. AI를 부르지 않아 비용이 없고, 제안 버튼은 빌더로 이어진다.
4. **W2 값 고정**: 단계 `data._pinned`. **시험·미리 보기 실행(trigger test·preview)에서만** 쓰고 실서비스 실행은 무시한다.
5. **O2 효과 리포트**: 앱 기능 `time_saved.minutes_per_run` × 성공한 실제 실행 수. 추정값이라고 화면에 적는다.
6. **Z1 안전 검사 단계**: 규칙 검사(개인정보·탈옥 문구·금지어·길이). 갈래를 늘리지 않고 `passed` 값으로 조건 분기에 맡겼다(분기 종류를 새로 만들면 검사기·캔버스·빌더를 다 고쳐야 해서). 모든 경우를 잡지 못한다고 단계 설명에 적었다.
7. **Y3 에이전트 도구 승인**: 도구마다 `approval`. 도구를 쓰려는 순간 실행을 멈추고 작업함에 승인 요청을 만든다. 에이전트 상태를 저장하지 않고 **승인·반려를 반영해 그 단계를 처음부터 다시 실행**한다(같은 도구·같은 값이면 지문이 같아 이번에는 실행). 그래서 AI 호출 비용이 한 번 더 든다.
8. **O1 평가 세트**: 질문·조건을 `features.eval`에 저장하고 케이스마다 실행(trigger `eval`)을 만들어 규칙 채점한다(실행 성공·포함·미포함·시간·JSON). AI 심판은 뒤로 미뤘다. 직전 묶음보다 통과율이 떨어지면 표시한다.
9. **C1 챗 허브**: 공유 링크로 배포된 앱 중 접근 권한이 맞는 것을 모아 보여 준다. 새 역할은 만들지 않았다(기존 `member` 역할이 쓰기 전용).
10. **X7 MCP로 만들고 고치기**: API 키 권한 `build`. `POST /service/mcp/build`가 빌더 툴 9개(ask_user·suggest_market_item 제외)를 내놓는다. **작업본만** 고치고 배포·버전 저장·키 관리는 못 한다. 키를 만든 사람이 지금도 제작자 이상일 때만 동작하고, 바꾼 호출은 활동 기록(`app.mcp_build`)에 남는다.
11. **Y2 스킬**: SKILL.md(앞머리 name·description + 본문)를 워크스페이스 설정(`settings.skills`)에 저장. 에이전트에는 `use_skill` 도구 하나로 붙이고 설명에 이름·설명만 싣는다(본문은 호출했을 때만).

## 대안
- 에이전트 승인에서 대화 상태를 저장했다가 이어 가기: 공급자별 내부 블록(생각 블록 등)을 저장해야 해서 깨지기 쉽다. 다시 실행을 택했다.
- 평가를 별도 표로 저장: 마이그레이션이 필요해서 앱 설정과 실행 기록(trigger eval)으로 대신했다.
- 키를 워크스페이스 단위로 만들기(X7): 새 표와 더 큰 권한이 필요해 앱 단위 키로 시작했다.

## 하지 않은 것(후보로 남김)
- 평가의 AI 심판 채점, 평가 결과를 배포 버튼에서 막기(지금은 경고 표시만).
- 스킬의 첨부 파일·마켓 품목화, 스킬 버전 관리.
- 챗 허브의 최근 쓴 앱·즐겨찾기.
- 에이전트 도구 승인의 승인 채널 선택(지금은 노드의 알림 설정을 그대로 씀).
- 효과 리포트의 갈래별 절약 시간.

## 영향
- 운영 반영: 마이그레이션 없음. API·웹 재빌드가 필요하다(`docker compose up -d`, `start_genio.bat -Rebuild`).
- 새 API 키 권한 `build`는 기본으로 꺼져 있다(키를 만들 때 직접 켠다).
- 에이전트 도구 승인은 승인 뒤 그 단계가 다시 실행되어 AI 사용량이 늘 수 있다.

## 2차 추가(같은 날)
- **Z2**: 막은 단계는 검사(시험 실행·버전 저장·빌더 목록)에서만 막고, 이미 배포된 버전의 실행은 막지 않는다(서비스가 갑자기 끊기지 않게). 시작·결과 단계는 막을 수 없다.
- **X4**: 규칙은 `<rules>` 안에 넣고 기본 규칙을 바꾸지 못한다고 못 박아 시스템 지시 끝에 붙인다.
- **Z4**: 가리기는 그대로 두고 소유자·관리자가 `?reveal=true`로 원문을 볼 수 있으며, 가리기가 켜진 워크스페이스에서만 열람을 기록한다.
- **O3**: 단계 설정의 id 칸(`credential_id`·`kb_id`·`table_id`·`app_id`·`skill_ids`)을 훑는다. `{{ }}`로 채우는 값은 알 수 없어 건너뛴다.
