# ADR 0016. 사용성 점검 반영 1차

- 상태: 채택
- 날짜: 2026-11-19

## 배경
처음 쓰는 비개발자(인사팀 담당자)가 되어 가입 → 첫 화면 → AI 없이 만들기 → 데모 AI → 말로 만들기 → 시험 → 배포 → 지식·데이터·연결·마켓·앱 설정을 직접 눌러 본 결과 어색한 점 9개와 현업 요구 16개를 골랐고(`docs/field-needs-2026-11-19.html`), 모두 진행하기로 했다.

## 결정
1. **마이그레이션을 만들지 않았다.** 새 설정은 모두 기존 JSON 칸에 담는다: 월간 리포트(`workspaces.settings.limits.monthly_report`, 진행 상태 `limits_state`), 점검 중(`apps.features.maintenance`), 문서 개인정보(`documents.doc_metadata._pii`), 메신저 서명 비밀값(`deployments.appearance._messenger`, Fernet 암호화).
2. **시험 모드는 요청 단위**(`POST /apps/{id}/runs`의 `dry_run`)이고 `trigger`가 test·preview일 때만 적용한다. 밖으로 내보내는 동작은 '읽기 이름 접두어'(get·list·search…)가 아닌 서비스 연결 동작으로 정했다(단계마다 표시를 새로 달지 않기 위해). API로 직접 호출하면 기본은 꺼짐이라 기존 동작이 그대로다. 화면의 테스트 실행은 보내는 단계가 있을 때만 칸을 보이고 기본 켜짐.
3. **배포 시 자동 저장**은 저장한 버전이 하나도 없을 때만 한다. 이미 버전이 있으면 새 버전을 만들지 않는다(작업본과 배포 버전이 달라지는 일을 막기 위해 일부러 자동 갱신은 하지 않음).
4. **고칠 질문**은 새 표 없이 메시지(`feedback`, 답 문구)에서 모은다. 처리하면 메시지의 `annotation_id`에 모범 답변 id(또는 `dismissed`)를 적어 모음에서 뺀다. 같은 질문은 공백·대소문자를 무시하고 묶어 한 번에 처리한다.
5. **메신저는 서명(HMAC)만 믿는다.** 슬랙은 서명+5분 안의 시각, 팀즈는 보안 토큰 HMAC. 슬랙의 `response_url`은 `hooks.slack.com`만 허용하고 `safe_http`로 보낸다. 연결하지 않은 앱은 존재도 알리지 않는다(404). 연결하면 그 슬랙·팀즈를 쓰는 누구나 앱에 물을 수 있다는 점을 화면에 적었다. 분당 30회 제한.
6. **시각**: `UTCDateTime`(TypeDecorator)로 모든 시각 열을 읽을 때 UTC를 붙인다. FastAPI가 반환 타입 표기를 보고 직접 직렬화해 `ENCODERS_BY_TYPE`가 먹지 않는 경로가 많았기 때문이다.
7. **모델 이름**: Fable 5.2를 추가하고 5.1은 '이전 버전'으로 남긴다(기존 연결이 깨지지 않게). 5.2 가격표는 공식 값을 확인하지 못해 5.1과 같게 두었다.

## 대안
- 시험 모드를 앱 설정으로 두기: 한 번 켜 두면 잊어버려 실제 발송이 막힌 채 배포될 수 있다고 봐서 요청 단위로 했다.
- 메신저 비밀값을 별도 표에 저장: 마이그레이션이 필요해 배포 줄의 JSON에 암호화해 두었다.
- 답 못한 질문을 AI로 판정: 비용·정확도 문제로 말 패턴(찾지 못했어요 등)과 싫어요로만 모았다.

## 하지 않은 것(후보로 남김)
- 고칠 질문이 생기면 담당자에게 메일·메신저로 알리기(지금은 탭에 건수만).
- 슬랙·팀즈 앱 마켓 등록, 사용자별 권한 연결(지금은 앱 단위로 공개 범위만 정함).
- (정정) 시험 모드의 HTTP·MCP·외부 API·하위 앱 확대는 ADR 0017에서 했다.
