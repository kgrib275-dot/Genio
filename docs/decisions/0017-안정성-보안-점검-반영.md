# ADR 0017. 안정성·보안 점검 반영

- 상태: 채택
- 날짜: 2026-11-19

## 배경
사용성 점검 1·2차 반영 뒤, 보안·동시성·안정성을 세 방향(신규 코드 보안 / 동시성·다중 인스턴스 / 기존 코드 전반)으로 읽기 전용 점검했다. 나온 항목을 위험이 큰 순서로 고쳤다. 점검은 코드를 읽어 한 것이고, 실제 PostgreSQL·다중 서버에서 재현하지는 못했다(시험은 SQLite).

## 결정(고친 것)
### 운영 노출
1. **운영 판정**: `GENIO_ENV`가 prod이거나 공개 주소(`GENIO_PUBLIC_WEB_URL`)가 localhost가 아니면 운영으로 본다. 운영에서는 비밀 키·암호화 키(`GENIO_FERNET_KEY`)가 비었거나 기본값이면 기동을 멈추고, **데모 계정(`owner@example.com` 등)을 시드하지 않는다.** `.env.example`의 `GENIO_SEED_DEMO` 기본값은 false.
2. **내부 주소 허용**: 서비스 내부 이름(postgres·redis·api…)·0.0.0.0·다른 표기의 루프백은 누구도 열 수 없고, 목록 변경은 서비스 관리자(가장 먼저 만든 워크스페이스 소유자)만 한다. docker compose는 `POSTGRES_PASSWORD`를 필수로 한다.
3. **시험 모드 확대**: 서비스 연결뿐 아니라 데이터를 바꾸는 HTTP(POST·PUT·PATCH·DELETE)·MCP·외부 API 도구, 그리고 그 안에서 부르는 하위 앱(`subflow`·`tool` 실행)까지 막는다. 읽기 판별은 '읽기 낱말로 시작하고 쓰기 낱말이 없을 때만'.
4. **메신저**: 공개 범위가 '누구나'가 아닌 앱은 연결·사용 모두 거절, 서명 확인 뒤에만 앱 단위 제한(확인 전에는 보낸 주소별), 같은 요청 5분 중복 제거(슬랙 재시도·재전송), 대화 이름에 서명 비밀값을 섞어 서버만 만들게 하고 공개 챗은 `slack:`·`teams:` 이름을 거절, 비ASCII 서명 헤더는 401, 블로킹 작업은 스레드 풀, 배포 모양을 저장해도 `_`로 시작하는 값(메신저 비밀값)은 보존.

### 동시성
5. **실행 선점**: 대기→실행 전환을 `UPDATE ... WHERE status='queued'`(원자적)로 한다. 이미 실행 중인 실행이 다시 전달돼도 처음부터 다시 돌지 않는다. PostgreSQL에서는 한도 확인과 시작 사이를 워크스페이스별 advisory lock으로 직렬화한다.
6. **결정 선점**: 사람 단계 결정은 `UPDATE human_tasks ... WHERE status='open'`으로 한 번만 반영, 승인 API는 행 잠금, 기한 처리는 처리 직전에 상태를 다시 확인한다.
7. **버전 저장**: 앱 행을 잠그고 채번한다. 제약 충돌(IntegrityError)은 영어 500 대신 한국어 409로 바꾼다. 빌더는 툴을 쓸 때마다 최신 작업본을 다시 읽고, 같은 대화에서 한 번에 한 차례만 받는다(3분 안에 답 없는 요청이 있으면 409).
8. **멈춘 실행 정리**: `genio.sweep_stuck_runs`(5분)가 5분 넘게 대기한 실행을 다시 큐에 넣고(최대 3번), 15분 넘게 '실행 중'인 실행은 실패로 표시한다. 큐 장애 시 `enqueue_run`은 예외 대신 경고만 남긴다(실행은 대기로 남아 위 점검이 처리).
9. **알림 메일**: 워크스페이스마다 별도 세션, 상태는 행 잠금으로 선점한 뒤 보내고 보내지 못하면 되돌린다(월 한도·월간 리포트). 설정 전체를 되쓰지 않고 `limits_state`만 갱신한다.
10. 그 밖: 문서 처리 선점(처리 중 문서는 일괄 재처리에서 제외), 소유권 이전 조건·멤버 행 잠금, 고칠 질문 저장 멱등, 서비스 키 `last_used_at` 1분 간격, 시작 advisory lock은 전용 연결에서 잡고 풀기, 속도 제한 메모리 폴백의 오래된 키 정리.

### 인증·입력
11. 비밀번호 변경·2단계 해제·복구 코드·탈퇴 확인은 계정별 15분 5회 실패 제한. 가입은 주소당 1시간 10회. TOTP는 한 번 받은 30초 번호(와 그 이전)를 다시 받지 않는다(`preferences.totp_last_step`).
12. AI 호출(OpenAI·Anthropic 호환)은 사용자가 적은 주소로 나갈 때 리다이렉트를 따라가지 않는다.
13. 코드 단계 자식 프로세스에 메모리 768MB·CPU 30초 한도(리눅스·맥), 문장 틀은 곱셈·거듭제곱 폭주와 100만 자 넘는 결과를 막는다. 공개 챗 `input` 20,000자, 웹훅·이벤트는 `Content-Length`를 먼저 본다.

## 이어서 한 것(같은 날)
- **PostgreSQL 동시 호출 시험**(`apps/api/tests/test_pg_concurrency.py`, 시험용 PostgreSQL 컨테이너에서): 같은 실행 8개 동시 선점→1개만 성공, 같은 승인 6번 동시 결정→1번만 반영, 버전 저장 6개 동시→번호 1~6, 첫 배포 4개 동시→모두 201, 알림 상태 8개 동시 선점→1개, 같은 문서 6개 워커 동시 처리→1번, 같은 대화 이름 6개 동시 시작→대화 1개. 마이그레이션 전체(0001~0021)가 PostgreSQL에서 위·아래·다시 위로 돈다는 것(0020 색인 포함)도 확인했다.
- **0021**: 대화 `(app_id, deployment_id, external_session_id)`·조각 `(document_id, position)` 유일 색인. 이미 겹쳐 있으면 대화는 이름 끝에 `~번호`를 붙여 구분하고 조각은 뒤쪽 것만 지운 뒤 만든다(겹친 데이터를 넣고 올려 보는 시험 포함). `start_chat`은 동시에 같은 대화를 만들면 한쪽만 남기고 나머지는 그 대화를 이어 쓴다.
- **api·worker 컨테이너 비루트(uid 10001)**: 이미지를 빌드해 비루트로 파일 저장 폴더 쓰기, 마이그레이션, API 기동(`/health` 200)을 확인했다. 리눅스에서 코드 단계의 `"a" * 10**10`이 메모리 한도(768MB)로 `MemoryError`가 나는 것도 확인했다. 기존 `filestore` 볼륨은 한 번 소유자를 바꿔야 한다(runbook).

## 하지 않은 것(이유)
- **Redis 비밀번호**: 포트가 127.0.0.1에만 열려 있고, 모든 연결 주소(REDIS_URL·브로커·결과 저장소)와 운영 절차를 함께 바꿔야 해서 별도 작업으로 남긴다.
- **AI 호출의 DNS 재바인딩 방지(IP 고정)**: 사내 AI 허용 목록을 호출 시점에 알아야 해서 남긴다(리다이렉트는 막음).
- **로그인 잠금 악용(계정 잠그기)**: 이메일+주소 조합 제한과 계정 전체 제한 사이의 선택이라 정책 결정이 필요해 남긴다.
- **신뢰 프록시 기본 범위**: Tailscale funnel이 실제 클라이언트 주소를 어떻게 넘기는지 확인한 뒤 줄인다.
- **작업 대기 중 실행의 한도 검사 직렬화 실증**: advisory lock 자체는 PostgreSQL 시험에 넣지 못했다(워커 여러 개가 필요).
