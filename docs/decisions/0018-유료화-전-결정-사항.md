# ADR 0018. 유료화 전에 정해야 할 것 (후보 — 아직 채택 아님)

- 상태: 제안(결정 대기)
- 날짜: 2026-11-23

## 배경
CLAUDE.md는 실제 결제·사용량 과금·SSO를 프로토타입 범위 밖으로 둔다([ADR 0011](0011-오픈-준비.md)). 판매형으로 가려면 아래를 먼저 정해야 한다. **이 문서는 결정 항목과 선택지를 모은 것이고, 구현은 하지 않는다.** 결정되면 새 ADR로 채택하고 그에 맞춰 만든다.

## 결정 1. AI 비용을 누가 내나 (가장 먼저)
| 선택지 | 설명 | 장점 | 위험 |
|---|---|---|---|
| A. 고객 키 사용(BYOK, 지금 방식) | 고객이 자기 AI 키를 넣는다 | 우리 원가 0, 키 악용 책임이 고객 | 비개발자에게 키 발급이 진입장벽 |
| B. 우리가 AI 제공 + 크레딧 판매 | 월 크레딧 포함, 초과분 추가 구매 | 가입 즉시 사용, 비개발자 친화 | 원가·악용·환율 위험, 사용량 정확 집계 필수 |
| C. 혼합 | 기본 크레딧 + 키를 넣으면 무제한 | 진입장벽↓, 원가 상한 | 두 경로 모두 유지 |
권장: C로 시작하되 크레딧은 보수적으로(체험용 소액), 악용 방어(가입당 한도, 이메일 인증 필수)를 먼저 갖춘다.

## 결정 2. 요금제(플랜) 구조
- 이미 있는 한도 틀(월 예산, 동시·분당 실행, 파일 용량, 앱별 하루 상한, 멤버 수)을 **플랜별 값으로 묶는 방식**을 권장한다. 새 한도 종류를 늘리지 않고 값만 바꾼다.
- 후보 축: 멤버 수 / 월 실행 수 / AI 크레딧 / 저장 용량 / 기능(품질 점검·메신저 연동·SSO).
- 체험(트라이얼): 기간(14일 등)과 종료 후 데이터 보관 기간(예: 30일), 보관 중 읽기 전용.

## 결정 3. 결제·청구
- 결제 대행사(PG): 국내 정기결제(빌링키) 지원 여부, 수수료, 정산 주기, 해외 카드. **카드 정보는 직접 저장하지 않고 PG에 맡긴다.**
- 세금계산서(사업자 고객), 부가세 표시, 환불·청약철회 처리, 결제 실패 시 재시도·유예 기간.
- 구독 상태 모델(trialing/active/past_due/canceled)과 상태별 기능 제한.

## 결정 4. 법·정책 (전문가 확인 필요)
- 사업자등록·통신판매업 신고, 이용약관·환불 정책·개인정보 처리방침 법률 검토(**지금 문서는 검토 전**).
- 개인정보 처리 위탁·국외 이전 고지(AI 제공사가 해외면 고객 문서가 해외로 나간다는 고지와 동의).
- 해지 후 데이터 보관·삭제 기한(백업 포함), SLA(약속하지 않을 거면 약관에 명시), AI 기본법 고영향 AI 해당 여부.

## 결정 5. 기업 고객
- SSO(사내 로그인), 계약·견적, 고객사별 데이터 격리·지역 선택, 감사 기록 장기 보관.

## 지금 만들어도 되는 것 (결제와 무관, 이 ADR과 별개로 진행)
서비스 공지, 상태 페이지, 첫 사용 성공률 지표, 관리자 2단계 인증 강제, 워크스페이스 데이터 내보내기(해지·이관 대비), 장애 알림. 구현 결과는 [feature-coverage](../feature-coverage.md)에 적는다.

## 결정이 끝난 뒤 만들 것(순서 제안)
1. 월 사용량 확정 집계(마감 후 수정 불가, 청구 근거) 2. 플랜 모델과 한도 묶기 3. 구독 상태와 기능 제한 4. PG 연동·영수증 5. 해지·환불·데이터 보관 화면 6. 청구서·결제 내역 화면.

## 출시 점검표 (유료·무료 공통)
- [ ] 실제 AI 키로 대표 시나리오 3개와 품질 점검 AI 심판 확인
- [ ] 실제 슬랙·팀즈·메일 연결 확인
- [ ] 전체 컨테이너 재빌드 리허설(마이그레이션 0019~0021, 비루트)
- [ ] 약관·개인정보 처리방침 법률 검토
- [ ] 데모 계정 제거, 이메일 인증(SMTP 설정 후) 켜기, 회원가입 정책 결정
- [ ] 외부 백업 설정과 복구 연습 결과 확인
- [ ] 장애 알림 수신자 지정, 상태 페이지 공개
- [ ] 부하 시험 갱신, 실제 휴대폰·다른 브라우저 점검
