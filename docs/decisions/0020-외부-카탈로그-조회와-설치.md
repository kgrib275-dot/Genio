# 0020. 외부 카탈로그 조회와 설치(MCP 레지스트리 먼저)

- 상태: 채택(1단계). 2단계(n8n 템플릿 변환)는 이 문서에 이어서 별도 결정한다.
- 날짜: 2026-11-23

## 배경
마켓은 제니오가 직접 올린 항목만 설치할 수 있다. 사용자는 "최신 서비스를 검색해서 바로 연결하고 싶다"고 한다.
공식 MCP 레지스트리(`registry.modelcontextprotocol.io`)는 공개 JSON API로 서버 목록을 준다(이름·설명·버전·원격 주소·필요한 헤더).

## 결정
1. **1단계: MCP 레지스트리 검색 → 연결.** 검색 결과에서 `streamable-http` 원격 주소가 있는 서버만 "연결하기"를 보여 준다.
   설치 = 기존 'MCP 서버 연결 정보'를 만드는 것과 같다(주소·토큰은 암호화 저장). 앱이나 코드는 만들지 않는다.
2. **회사별로 켜야 쓸 수 있다.** `workspace.settings["security"]["external_catalog"]`, 기본 꺼짐. 켜고 끄는 것은 소유자·관리자.
3. **서버가 다시 조회한다.** 설치 요청에는 레지스트리의 서버 이름만 받고, 주소는 서버가 레지스트리에서 다시 읽는다(클라이언트가 임의 주소를 끼워 넣지 못하게).
4. **안전 장치.** 모든 외부 호출은 `safe_http`(사설망 차단·시간·크기 제한)를 거친다. 조회는 사용자당 분당 20회, 결과는 5분 캐시한다.
   자리표시자(`{...}`)가 들어간 주소는 설치하지 않는다. 비밀값은 사용자가 직접 넣는다. 외부 코드는 실행하지 않는다.
5. **기록.** 조회(10분에 한 번)와 설치는 활동 기록(`catalog.search`, `catalog.install`)에 남긴다. 설치는 연결 정보 권한(소유자·관리자)만, 조회는 제작자 이상.
   지원 접속으로는 설치할 수 없다(연결 정보 권한).

## 대안
- 자동으로 가장 인기 있는 서버를 설치: 신뢰할 수 없는 서버에 자동 연결되므로 기각.
- 레지스트리를 제니오 DB에 복제: 최신성이 떨어지고 운영 부담이 커서 기각(실시간 조회 + 짧은 캐시).

## 영향
- 새 API: `GET /workspaces/{ws}/catalog/mcp`, `POST /workspaces/{ws}/catalog/mcp/install`, 보안 설정에 `external_catalog`.
- 신뢰 문제: 레지스트리 항목은 누구나 올릴 수 있다. 화면에 출처(저장소 주소)를 보여 주고, 연결 후 '도구 보기'로 확인하게 안내한다.
- 사용 조건·레이트리밋은 공식 문서에서 확인하지 못했다. 캐시와 호출 제한으로 부담을 줄이고, 문제가 생기면 끌 수 있게 했다.
