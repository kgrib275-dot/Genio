# 0022. 역할별 메뉴와 목표별 단계 안내

- 상태: 채택(구조 먼저, 메뉴 이름 변경은 보류)
- 날짜: 2026-11-23

## 배경
메뉴가 역할과 거의 같아서 일반 멤버도 지식베이스·데이터 표·연결 정보·마켓 같은 '만드는 도구'를 모두 봤다. 이름도 개념 중심(지식베이스, 연결 정보, 워크스페이스 …)이라 비개발자가 "무엇을 하는 곳인지" 알기 어렵다. 일반 멤버의 첫 화면은 샘플 앱 목록(기술 용어 포함)이었다.

## 결정
1. **역할 이름은 화면에서 소유자·관리자·제작자·사용자 네 가지로 말한다.** 서버에는 운영자(operator, 실행 기록 보기)가 하나 더 있다. 권한 구조는 바꾸지 않고(컬럼·역할 삭제 금지) 메뉴에서는 **운영자를 사용자와 같게** 보여 준다.
2. **사이드바를 업무 말로 묶는다.**
   - 쓰기(모두): 대시보드·챗봇 모음·작업함
   - 만들기(제작자 이상): 지식베이스·데이터 표·연결 정보·마켓
   - 팀: 워크스페이스, 관리(관리자·소유자)
   - 묶음이 하나뿐이면 묶음 이름은 붙이지 않는다. 메뉴를 숨길 뿐 주소를 막지는 않는다(권한은 서버가 계속 확인한다).
   - '배우기'(앱 만드는 강좌)와 그 화면 투어 단계도 제작자 이상에게만 보인다.
3. **목표별 단계 안내(가이드)** — 대시보드의 "무엇을 하고 싶으세요?" 카드에서 고르면 단계마다 할 일·눌러야 할 버튼을 보여 주고, 화면을 옮겨 다녀도 왼쪽 아래 안내 창이 따라온다.
   - 만드는 사람: 내 문서로 답하는 챗봇 · 반복 업무 자동화 · 승인 받는 흐름 · 외부 서비스 연결(각 4단계)
   - 쓰는 사람: 챗봇에게 물어보기 · 내가 할 일 처리하기(각 3단계)
   - 진행 상태는 이 브라우저(localStorage)에만 둔다. 단계는 사람이 '했어요'로 넘긴다(자동 판정은 하지 않는다).
4. **메뉴 이름(지식베이스 → 문서 자료 등)은 바꾸지 않는다.** 써 보시고 정한다(도움말·문서도 같이 고쳐야 해서).

## 대안
- 역할마다 완전히 다른 앱 화면: 유지 비용이 크고 권한이 늘 때 어긋나기 쉬워 기각.
- 마법사로 화면을 막고 진행: 숙련자를 방해해서 기각(접을 수 있는 카드 + 따라오는 안내 창).

## 영향
- 기존 사용자가 메뉴 구조 변화에 낯설 수 있다(이름은 그대로라 찾기는 쉽다).
- 가이드는 정적 안내라서 화면이 바뀌면 문구를 함께 고쳐야 한다. 실제 비개발자 사용 관찰로 검증하는 것이 남아 있다.
