# Genio 기능 정의서 — 필수 기능과 강점 기능
기준: Dify(LLM 앱 빌더), n8n(범용 자동화)의 핵심 기능을 분석해 "반드시 있어야 하는 것"과 "우리가 더 잘해야 하는 것"으로 나눈다.
우선순위: P0 = 프로토타입 필수 / P1 = 정식 출시 필수 / P2 = 이후.
`docs/design.md`와 함께 읽는다. 충돌 시 이 문서가 기능 범위의 기준, design.md가 구현 방식의 기준이다.
반영 현황은 `docs/feature-coverage.md`에서 항목별로 관리한다.

---

## Part 2. Genio의 강점으로 만들 기능 (Dify·n8n에 없거나 약한 것)

### S1. 대화형 빌더 (가장 큰 차별점) — P0
- Dify·n8n 모두 "사람이 노드를 끌어야" 한다. Genio는 말로 시키면 빌더가 만든다.
- 필수 세부 기능:
  - 자연어 → 워크플로우 생성(툴 호출 기반, design.md §6)
  - 되묻기: 빠진 정보를 선택지 버튼으로 질문
  - 수정 대화: "두 번째 노드 온도 낮춰", "슬랙 대신 이메일로" 같은 부분 수정
  - 설명 모드: 기존 워크플로우를 골라 "이거 뭐 하는 거야?" → 노드별 설명
  - 테스트 자동화: 만들고 나서 빌더가 샘플 입력으로 돌려 보고 결과 요약
  - 오류 해결: 실행 실패 시 "왜 실패했어?" → 원인 + 고쳐 줄까 제안 → 패치
  - 마켓 연계: 없는 커넥터·노드를 마켓에서 찾아 설치 제안
- 측정 지표: 첫 요청에서 동작하는 앱까지 걸린 시간, 수정 대화 횟수, 사람이 캔버스를 직접 만진 비율

### S2. 비개발자 언어로 된 UI — P0
- n8n은 개발자용, Dify도 "변수·노드·DSL" 용어 그대로. Genio는 모든 문구를 업무 언어로.
- "워크플로우 → 흐름", "노드 → 단계", "credential → 연결 정보", "webhook → 외부에서 받기", "variable → 값".
- 노드 설정 폼은 JSON Schema 기반 자동 생성이지만 라벨·도움말·예시는 한국어 업무 문장으로.
- 표현식 `{{ }}`는 "값 끌어오기" 버튼으로 숨기고, 고급 모드에서만 직접 편집.

### S3. 실행 결과를 "설명"으로 보여 주기 — P0
- 노드별 JSON 덤프 대신 "분류 단계에서 '결제 문의'로 판단 → #billing 채널로 전송 완료(0.8초)" 식 문장 로그. JSON은 펼쳐 보기.
- 실패 시 "무엇이 문제 + 어떻게 하면 되는지" 두 줄 + "빌더에게 고쳐 달라고 하기" 버튼.

### S4. 권한이 처음부터 있는 구조 — P0
- Dify 커뮤니티판·n8n 셀프호스팅은 권한이 약하거나 유료. Genio는 조직·역할·앱별 접근·감사 로그를 기본 제공.
- 자격증명은 워크스페이스 귀속, 빌더는 선택만, 운영자는 로그만 — 실제 기업 도입 시 가장 먼저 묻는 것.
- 앱 배포 시 "누가 쓸 수 있나"를 역할·사용자 단위로 지정.

### S5. 마켓이 빌더와 연결된 생태계 — P0(설치) / P1(사내 공유) / P2(외부 판매)
- n8n 커뮤니티 노드·Dify 플러그인은 "찾아서 설치"해야 한다. Genio는 빌더가 필요할 때 제안하고 한 번에 설치.
- 설치된 아이템은 즉시 빌더 카탈로그에 반영되어 다음 대화부터 쓸 수 있음.
- 사내 마켓: 팀이 만든 템플릿을 조직 안에서 공유·설치(정식 출시 핵심).

### S6. 한국 업무 환경 커넥터 — P1
- 카카오 알림톡·카카오톡 채널, 네이버웍스, 잔디, 더존·영림원 ERP(가능한 범위), 국세청 홈택스 API, 공공데이터포털, 네이버 클라우드.
- 글로벌 제품이 약한 지점. 초기엔 카카오 알림톡·네이버웍스·잔디 3개만.

### S7. 사람 개입이 자연스러운 워크플로우 — P0(승인) / P1(질문·배정)
- 승인 노드: 승인자에게 슬랙·이메일·카카오로 요청, 링크에서 승인/반려 + 코멘트, 반려 시 분기.
- 질문 노드: 실행 중 담당자에게 추가 정보 요청 후 재개.
- 담당자 배정 노드: 조건에 따라 사람에게 작업 배정 + 완료 체크.
- 챗봇 → 상담원 전환: 챗봇이 못 풀면 사람에게 넘기고 대화 이력 전달(컨택센터 사업과 직결).

### S8. 비용·품질 가시성 — P0(비용) / P1(품질)
- 앱별·사용자별 비용, 월 한도, 모델 교체 시 예상 비용 비교.
- 품질: 답변 피드백(좋아요/싫어요) 비율, 출처 없는 답변 비율, 자주 실패하는 질문 목록 → 빌더가 "이 질문들 개선할까요?" 제안.

### S9. 챗봇 ↔ 워크플로우 양방향 — P0
- Dify는 챗봇 중심, n8n은 자동화 중심. Genio는 하나의 앱에서 챗봇 대화 중에 워크플로우를 호출하고(예: "휴가 신청해 줘" → 승인 워크플로우 실행), 워크플로우가 끝나면 챗으로 결과를 돌려준다.
- 챗 트리거 + 워크플로우 트리거를 같은 그래프에서 혼용 가능.

### S10. 템플릿이 "업무 단위" — P1
- 노드 템플릿이 아니라 "고객 문의 분류·배정", "주간 보고 자동 작성", "신규 입사자 온보딩 Q&A", "견적 요청 처리", "계약서 검토 보조" 같은 완성 업무 단위. 설치 후 빌더가 "슬랙 채널만 알려 주세요"처럼 빈칸만 채우게.
