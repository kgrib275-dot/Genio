- 방법: Playwright(설치된 Chrome)로 가입·로그인 후 모든 경로를 열고, 화면의 탭을 차례로 눌러 보며 다음을 모았다: 콘솔 오류, 페이지 오류, 서버 오류(5xx)·예상 밖 4xx, 화면에 드러난 개발자 문구(`undefined`·`NaN`·`[object Object]`·영어 오류 등), 가로 넘침(데스크톱 1440px, 모바일 390px).
- 대상(35개): 대시보드, 앱(개요·빌더·설정·실행 기록·기능·로그·모니터링·API·자동 실행), 실행 상세, 지식베이스, 데이터 표, 연결 정보, 마켓·상세, 워크스페이스, 관리, 도움말, 내 설정, 작업함, 배우기, 프로젝트, 없는 주소, API 문서, 약관, 개인정보, 공유 챗 / 로그인 전: 로그인, 가입, 비밀번호 찾기, 잘못된 재설정·메일 확인·초대·공유 링크.
- 결과: 오류 0건. 빌더의 탭 8건은 점검 방법상의 오탐이었다(모바일 전용 탭이라 데스크톱에서 숨김, 함께 편집 접속 채널이 열려 있어 '네트워크 조용함'을 기다리다 시간 초과). 모바일 폭에서 탭 4개 모두 눌러 오류 없음을 따로 확인했다.
- 고친 문구:
  - 잘못된 초대 링크: "초대을(를) 찾을 수 없어요 / 목록에서 다시 선택하세요" → "초대 링크를 찾을 수 없어요 / 받은 링크가 끝까지 복사됐는지 확인하거나, 관리자에게 새 초대를 요청하세요". 다른 '찾을 수 없어요' 문구도 받침에 맞춰 을/를을 붙이게 고쳤다(예: "멤버를 찾을 수 없어요").

## 5. 운영 반영 상태
- 운영 API·워커는 코드 폴더를 그대로 쓰므로, 위 Docker 재시작 때 이 점검의 서버 쪽 수정(샌드박스·인증·초대 등) 대부분이 **이미 운영에 반영된 상태**다. 마지막 문구 수정(을/를, 초대 링크 문구)은 `docker compose restart api worker`를 해야 반영된다.
- 화면 쪽 수정(초대 수락 단추, 이동 주소 검사, dompurify, 문구)은 `start_genio.bat -Rebuild`로 웹을 다시 빌드해야 반영된다. 이 PC는 메모리가 빠듯하므로 다른 시험 스택(`genio-lt`)을 내린 뒤 빌드할 것.
